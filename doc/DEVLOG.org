* 2026-03-22 — Comparison: DSMR Configuration vs. Sagredo Reference Stack

** Overview

Comparison of the three DSMR Debian packages (~dsmr-qmail~, ~dsmr-vpopmail~,
~dsmr-dovecot~) against the configuration documented at
[[https://notes.sagredo.eu/en/qmail-notes-185/qmail-vpopmail-dovecot-roberto-s-qmail-notes-8.html][notes.sagredo.eu]] (Roberto Puzzanghera's qmail notes).  The sagredo stack is a
source-compiled "qmail toaster" targeting Slackware/generic Linux.  DSMR
targets Debian 13 Trixie and uses packaged dovecot.  Differences are annotated
as *gap*, *deliberate*, or *alignment* (already matching).

Reference sources used:
- [[https://notes.sagredo.eu/en/qmail-notes-185/installing-and-configuring-vpopmail-81.html][Installing vpopmail]]
- [[https://notes.sagredo.eu/en/qmail-notes-185/configuring-qmail-83.html][Configuring qmail]]
- [[https://notes.sagredo.eu/en/qmail-notes-185/installing-dovecot-and-sieve-on-a-vpopmail-qmail-server-28.html][Installing dovecot + sieve]]
- [[https://notes.sagredo.eu/en/qmail-notes-185/running-dovecot-32.html][Running dovecot]]
- [[https://github.com/sagredo-dev/dovecot-conf][sagredo-dev/dovecot-conf on GitHub]]

** dovecot Configuration

*** Authentication: SQL passdb query

*Sagredo* uses a complex query with LEFT JOINs on the ~aliasdomains~ and
~limits~ tables, quota extraction from ~pw_shell~, and per-user access-control
flags (disable_webmail, disable_imap, disable_pop3) gated by ~vpopmail.pw_gid~
bit-field:

#+BEGIN_SRC sql
passdb sql {
  query = \
    SELECT \
      CONCAT(vpopmail.pw_name, '@', vpopmail.pw_domain) AS user, \
      vpopmail.pw_passwd AS password, \
      vpopmail.pw_dir AS userdb_home, \
      89 AS userdb_uid, \
      89 AS userdb_gid, \
      CONCAT(REPLACE(SUBSTRING_INDEX(vpopmail.pw_shell, 'S', 1), 'NOQUOTA', '0'), 'B')
          AS userdb_quota_storage_size \
    FROM vpopmail \
      LEFT JOIN aliasdomains ON aliasdomains.alias='%{user | domain}' \
      LEFT JOIN limits       ON limits.domain='%{user | domain}' \
    WHERE \
      vpopmail.pw_name='%{user | username}' \
      AND (vpopmail.pw_domain='%{user | domain}' OR vpopmail.pw_domain=aliasdomains.domain) \
      AND ('%{local_port}'!='995' OR !(vpopmail.pw_gid & 2)) \
      AND ('%{remote_ip}'!='127.0.0.1' OR !(vpopmail.pw_gid & 4)) \
      AND ('%{remote_ip}'='127.0.0.1' OR '%{local_port}'!='993' OR !(vpopmail.pw_gid & 8)) \
      AND ('%{remote_ip}'!='127.0.0.1' OR COALESCE(disable_webmail,0)!=1) \
      AND ('%{remote_ip}'='127.0.0.1' OR COALESCE(disable_imap,0)!=1)
}
#+END_SRC

*DSMR* (~vpopmail-auth-sql.conf.ext~) uses a simpler query with no joins, no
quota, and no per-user access flags:

#+BEGIN_SRC sql
passdb sql {
  default_password_scheme = SHA512-CRYPT
  query = \
    SELECT pw_passwd AS password, pw_dir AS userdb_home, \
           89 AS userdb_uid, 89 AS userdb_gid \
    FROM vpopmail \
    WHERE pw_name = '%{user|username}' AND pw_domain = '%{user|domain}'
}
#+END_SRC

Note also a scope difference: sagredo sets ~passdb_default_password_scheme = SHA512-CRYPT~
at the top level of ~auth-sql.conf.ext~ (alongside ~auth_allow_weak_schemes = yes~ for
legacy MD5 compatibility), and also sets ~sql_driver = mysql~ at top level.  DSMR sets
~default_password_scheme = SHA512-CRYPT~ inside the ~passdb sql {}~ block and puts the
MySQL connection block in a separately generated file (~dovecot-vpopmail-sql.conf.ext~).
Both approaches are valid; DSMR's separation is cleaner.

Status: *gap* — DSMR query is missing:
- Alias domain support (LEFT JOIN aliasdomains)
- Per-domain limits JOIN
- Quota extraction from ~pw_shell~
- Per-user access flags (disable_imap, disable_webmail, disable_pop3)

This is only actionable if vpopmail is compiled with
~--enable-sql-aliasdomains~ and ~--enable-mysql-limits~ (see vpopmail section
below).

*** Authentication: userdb approach

*Sagredo* uses ~userdb prefetch~ (reuses fields returned by passdb) plus
~userdb sql~ as a fallback for LDA and iteration.

*DSMR* uses only ~userdb sql~ (no prefetch).

Status: *gap* — adding ~userdb prefetch~ before ~userdb sql~ would reduce
database round-trips on every login.

*** Authentication: system user passdb fallback

*Sagredo*: no system user (passwd-file) fallback documented.

*DSMR*: adds ~passdb passwd-file~ + ~userdb passwd-file~ pointing to
~/etc/dovecot/system-passwd~ (root:dovecot 640) with
~auth_username_format = %{user|username}~ to strip the domain.  Created empty
by postinst.

Status: *deliberate addition* — DSMR extends sagredo's design to support local
Unix users reachable via IMAP with ~user@defaultdomain~ addressing.

*** Mail location and INBOX mapping

*Sagredo* (~10-mail.conf~):

#+BEGIN_SRC
mail_driver = maildir
mail_path = ~/Maildir
# mail_inbox_path is commented out — uses dovecot default (.INBOX subdirectory)
mailbox_list_validate_fs_names = no
maildir_broken_filename_sizes = yes
#+END_SRC

*DSMR* (~99-vpopmail-mail.conf~):

#+BEGIN_SRC
mail_driver = maildir
mail_path = ~/Maildir
mail_inbox_path = ~/Maildir        # explicitly maps INBOX to Maildir root
#+END_SRC

Status: *deliberate divergence* — DSMR sets ~mail_inbox_path = ~/Maildir~ so
that dovecot's INBOX is the Maildir root (new/, cur/, tmp/ directly), matching
qmail/vdelivermail delivery.  Sagredo leaves this unset, which under dovecot
2.4 defaults would place INBOX at ~~/Maildir/.INBOX/~, incompatible with
vdelivermail.  The DSMR setting is correct for this stack.

The sagredo repo has ~mail_inbox_path = ~/Maildir/~ commented out, suggesting
awareness of the issue but leaving it to local.conf.

*DSMR is missing* from sagredo's ~10-mail.conf~:
- ~mailbox_list_validate_fs_names = no~ (allows dots in mailbox names like Junk.TeachSpam)
- ~maildir_broken_filename_sizes = yes~
- ~mail_privileged_group = 89~
- ~mail_access_groups = 89~
- ~mail_plugins { notify = yes }~

*** UID/GID validity range

*Sagredo*:
#+BEGIN_SRC
first_valid_uid = 89
last_valid_uid  = 89   # strict — vpopmail-only
first_valid_gid = 89
last_valid_gid  = 89
#+END_SRC

*DSMR*:
#+BEGIN_SRC
first_valid_uid = 89
last_valid_uid  = 0    # 0 = unlimited, allows system users (uid ≥ 1000)
first_valid_gid = 89
last_valid_gid  = 0
#+END_SRC

Status: *deliberate divergence* — DSMR loosens the range to permit system user
authentication via the passwd-file passdb.  If system-user support is not
required, reverting to ~last_valid_uid = 89~ tightens the security posture.

*** TLS certificate paths

| Setting              | Sagredo                      | DSMR                             |
|----------------------+------------------------------+----------------------------------|
| ~ssl_server_cert_file~ | ~/etc/ssl/certs/dovecot.pem~   | ~/etc/dovecot/private/dovecot.pem~ |
| ~ssl_server_key_file~  | ~/etc/ssl/private/dovecot.pem~ | ~/etc/dovecot/private/dovecot.key~ |

Status: *minor divergence* — DSMR uses a package-local directory and splits
the key file extension to ~.key~ (clearer naming).  Both are valid.  Sagredo
also documents Let's Encrypt paths.

*** SSL minimum protocol

*Sagredo*: ~ssl_min_protocol = TLSv1~ (permits TLS 1.0/1.1).

*DSMR* (~99-vpopmail-ssl.conf~): only sets ~ssl = required~; minimum protocol
version is left to dovecot's compiled-in default (TLSv1.2 on Debian 13).

Status: *DSMR is stricter* — the sagredo setting is permissive legacy
compatibility.  DSMR's behavior is better.

*** Service management

*Sagredo*: source-compiled binary at ~/usr/local/dovecot/sbin/dovecot~.  Run
via either ~rc.local~ or a daemontools supervise service under
~/var/qmail/supervise/dovecot~.

*DSMR*: Debian package; managed by systemd (~dovecot.service~).

Status: *deliberate* — systemd is the correct integration point on Debian 13.

*** Missing dovecot features (sagredo has; DSMR does not)

| Feature                      | Sagredo                                  | DSMR |
|------------------------------+------------------------------------------+------|
| POP3/POP3S (ports 110/995)   | Yes (~protocols { pop3 = yes }~)           | No   |
| Quota (count driver)         | Yes (~90-quota.conf~, warnings)            | No   |
| Sieve / ManageSieve          | Yes (~90-sieve.conf~, ~20-managesieve.conf~) | No   |
| FTS / Solr                   | Yes (~fts_solr~ plugin)                    | No   |
| Postlogin script             | Yes (updates ~vpopmail.lastauth~)          | No   |
| Per-mailbox auto-subscribe   | Yes (~15-mailboxes.conf~)                  | No   |
| stats service unix listeners | Yes (vpopmail:vchkpw 0660)               | No   |
| ~auth_allow_weak_schemes~      | Yes (legacy MD5 compatibility)           | No   |

All are optional enhancements.  None are required for basic IMAP+auth.

Critical gap: ~--enable-many-domains~ and ~--enable-sql-aliasdomains~ are
prerequisites for the sagredo SQL passdb query (the LEFT JOIN on
~aliasdomains~) to work.  Without them, the DSMR simplified query is correct
but loses alias domain and per-domain limits support.

*** MySQL GRANT scope

*Sagredo*:
#+BEGIN_SRC sql
GRANT ALL PRIVILEGES ON `vpopmail`.* TO 'vpopmail'@'mailserver-IP';
#+END_SRC

*DSMR*:
#+BEGIN_SRC sql
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, INDEX
  ON `vpopmail`.* TO 'vpopmail'@'localhost';
#+END_SRC

Status: *DSMR is more restrictive* (deliberate).  ~ALL PRIVILEGES~ grants
~GRANT OPTION~, ~LOCK TABLES~, etc.  DSMR's set covers everything vpopmail
tools actually use (~CREATE/DROP~ for domain table creation, ~INDEX~ for
~qmail-newu~-related activity).  The more restrictive grant is preferable.

*** vpopmail.mysql credential file

Both use ~host|port|user|password|database~ pipe-delimited format.

*Sagredo* documents manual creation.  *DSMR* postinst generates it
automatically with a random 24-character password.

Status: *DSMR improvement*.

*** SMTP port 465 (SMTPS)

*Sagredo* runs a ~qmail-smtpsd~ supervise service on port 465 using
~ucspi-ssl~'s ~sslserver~ with TLS-from-connect.

*DSMR* has no port 465 service; submission is port 587 only.

Status: *gap* — port 465 is deprecated by RFC but still widely used.

*** TCP rules

*Sagredo* tcp.smtp:
#+BEGIN_SRC
0.0.0.0:allow,RELAYCLIENT="",SMTPD_GREETDELAY="0"
127.:allow,RELAYCLIENT="",SMTPD_GREETDELAY="0"
:allow,CHKUSER_WRONGRCPTLIMIT="3"
#+END_SRC

*DSMR* tcp.smtp:
#+BEGIN_SRC
127.:allow,RELAYCLIENT=""
:allow
#+END_SRC

Status: *gap* — DSMR is missing ~CHKUSER_WRONGRCPTLIMIT~ and the localhost
~SMTPD_GREETDELAY="0"~ override.

*** qmail-send/run

*Sagredo* (simplified): ~exec $QMAILDIR/rc~

*DSMR*: conditionally wraps with ~spawn-filter~ (DKIM signing) if ~filterargs~
is present, otherwise falls back to plain ~qmail-start ./Maildir~.

Status: *DSMR improvement* — explicit DKIM integration without requiring a
separate ~rc~ script.

** Recommended Near-Term Actions

1. *~99-vpopmail-mail.conf~*: Add ~mailbox_list_validate_fs_names = no~ and
   ~maildir_broken_filename_sizes = yes~ to match sagredo's mail config.  Low
   risk, no functional change for current users.

2. *qmail control files*: Add ~databytes~ and ~maxrcpt~ to the postinst-generated
   set.  Both are production hardening; neither affects current behavior.

3. *vpopmail configure flags*: Evaluate adding ~--enable-many-domains~,
   ~--enable-sql-aliasdomains~, and ~--enable-mysql-limits~ when alias domain
   or quota support is needed.  Requires schema migration (new ~aliasdomains~
   and ~limits~ tables) and SQL passdb query update.

4. *dovecot userdb prefetch*: Straightforward performance improvement — add
   ~userdb prefetch {}~ before ~userdb sql~ in ~vpopmail-auth-sql.conf.ext~.
