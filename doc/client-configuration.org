#+TITLE: Configuring External Mail Clients (full-stack profile)
#+AUTHOR: Brian O'Reilly
#+OPTIONS: toc:2 num:t
#+STARTUP: overview

How to configure an external mail client (Thunderbird, Apple Mail, Outlook,
mobile, mutt, …) to read and send mail through a DSMR host, for both account
types the full stack serves: *system accounts* (shell/Unix users) and *vpopmail
accounts* (virtual users).

Substitute your own values for the placeholders:

| Placeholder | Example          | Meaning              |
|-------------+------------------+----------------------|
| =MAILHOST=  | mail.example.com | the mail server FQDN |
| =DOMAIN=    | example.com      | a hosted mail domain |

* Server settings at a glance
| Purpose          | Protocol | Host       | Port | Security | Auth     |
|------------------+----------+------------+------+----------+----------|
| Reading (IMAP)   | IMAP     | =MAILHOST= |  993 | SSL/TLS  | password |
| Reading (IMAP)   | IMAP     | =MAILHOST= |  143 | STARTTLS | password |
| Sending (submit) | SMTP     | =MAILHOST= |  587 | STARTTLS | password |

- *TLS is mandatory.* The server sets =ssl = required=, so a client must use
  SSL/TLS (port 993) or STARTTLS (port 143); plaintext IMAP is refused. The
  submission port (587) requires STARTTLS and always requires authentication.
- *POP3 is not offered* by default; use IMAP.
- *Implicit-TLS submission (port 465) is not offered*; use 587 + STARTTLS.
- The server certificate is =/etc/qmail/servercert.pem=. If it is self-signed,
  import it into the client (or accept it once) to avoid TLS warnings.
- The same credentials work for *both* reading and sending — the server
  authenticates IMAP and submission against one chained source
  (vpopmail SQL → =/etc/dovecot/system-passwd= → PAM).

* Account types and usernames
Both populations enter the *full email address* =user@DOMAIN= as the username;
only the password source differs:

| Account type       | Username to enter          | Password                                                                                                                            |
|--------------------+----------------------------+-------------------------------------------------------------------------------------------------------------------------------------|
| vpopmail (virtual) | full address =user@DOMAIN= | the mailbox password (set with =vpasswd= / vpopmail)                                                                                |
| system (shell)     | full address =user@DOMAIN= | the mail password from =/etc/dovecot/system-passwd= (set with =dsmr-smtpauth=, intentionally separate from the Unix login password) |

Use the *same* username/password pair in both the incoming (IMAP) and outgoing
(SMTP) sections of the client.

* System users: ready-made settings in =~/RELAY_AUTH.txt=
When an administrator sets up a *system (shell) user* for authenticated mail
with =dsmr-smtpauth= (its =add= or =passwd= command), a file named
=RELAY_AUTH.txt= is written to that user's home directory with everything in
this guide already filled in for the host:

- the account's email address (=user@DOMAIN=),
- the mail password just set (separate from the Unix login password),
- the submission and IMAP servers, ports, and connection security, and
- step-by-step setup instructions for Thunderbird and Apple Mail.

The file is mode =0600= and owned by the user, so only that user (and root) can
read it. It is rewritten whenever the mail password is changed and removed when
the credential is revoked (=dsmr-smtpauth del=). A system user configuring a
client can usually just open =~/RELAY_AUTH.txt= and copy the values, instead of
substituting the placeholders below by hand.

This applies to *system accounts only*. A *vpopmail (virtual) user* has no shell
account and therefore no =RELAY_AUTH.txt=; those settings come from this guide,
using the mailbox password set with =vpasswd=.

* Reading mail (IMAP)
Common settings for any client:
- Server / hostname: =MAILHOST=
- Port / security: =993= with SSL/TLS (preferred), or =143= with STARTTLS
- Authentication: normal password (the server offers PLAIN/LOGIN over TLS)
- Mailbox layout: Maildir; INBOX is the Maildir root (=~/Maildir=). New mail
  arrives in =~/Maildir/new/=.

** vpopmail account
- Username: =user@DOMAIN= (the full email address)
- Password: the mailbox password

** system account
- Username: =user@DOMAIN= (the full email address, e.g. =alice@example.com=)
- Password: the account's mail password from =/etc/dovecot/system-passwd=
- The account must have a =system-passwd= entry with full uid/gid/home/shell
  (created by =dsmr-smtpauth=); dovecot uses the home to locate =~/Maildir=.
  A bare =user:hash= entry authenticates but breaks IMAP because dovecot 2.4
  needs the home directory from the userdb.

* Sending mail (SMTP submission)
Common settings for any client:
- Server / hostname: =MAILHOST=
- Port: =587=, connection security: STARTTLS
- Authentication: required, normal password (PLAIN/LOGIN over TLS)
- Note: authentication is mandatory on 587 — an unauthenticated client cannot
  relay. Once authenticated, the client may send to any destination.

** vpopmail account
- Username: =user@DOMAIN=
- Password: the mailbox password (same as IMAP)

** system account
- Username: =user@DOMAIN= (the full email address). The submission service sets
  =FORCEAUTHMAILFROM=, so the address you authenticate as must equal the =From=
  address you send — use =user@DOMAIN= for both. (Dovecot strips the domain when
  checking =system-passwd=, so the login still resolves to the =user= row.)
- Password: the =system-passwd= mail password (same as IMAP)

* Worked example (Thunderbird / generic client)
For a vpopmail user =alice@example.com= on host =mail.example.com=:

| Field               | Incoming (IMAP)   | Outgoing (SMTP)   |
|---------------------+-------------------+-------------------|
| Server              | mail.example.com  | mail.example.com  |
| Port                | 993               | 587               |
| Connection security | SSL/TLS           | STARTTLS          |
| Authentication      | Normal password   | Normal password   |
| Username            | alice@example.com | alice@example.com |

For a system user =alice= on the same host, use username =alice@example.com=
(and the =system-passwd= password) in both columns; all other fields are
identical.

* Troubleshooting
- *Unsure of your server, port, or password (system user)* — open
  =~/RELAY_AUTH.txt= in your home directory; it holds the current values and the
  per-client steps. If it is missing, ask the administrator to (re-)run
  =dsmr-smtpauth passwd <you>=.
- *TLS / certificate warning* — expected with a self-signed
  =/etc/qmail/servercert.pem=; import or trust the certificate.
- *IMAP login fails for a system user* — confirm the account is listed:
  =dsmr-smtpauth list=; confirm the entry has uid/gid/home/shell (not a bare
  hash). Re-set the password with =dsmr-smtpauth passwd user=.
- *IMAP login fails for a vpopmail user* — verify with
  =vuserinfo user@DOMAIN= and reset with =vpasswd user@DOMAIN=.
- *Sending rejected with "relaying denied"* — the outgoing server is not
  authenticating; ensure the client uses port 587 with authentication enabled.
- *Sending rejected with 5xx on a local recipient* — recipient validation; see
  the system-first routing docs shipped with =dsmr-localfirst=.
- *Plaintext connection refused* — TLS is required; switch the client to
  SSL/TLS or STARTTLS.
