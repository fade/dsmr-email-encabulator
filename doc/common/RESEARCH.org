* Overview

This document records the investigation of the current state of the qmail
Debian packaging project at ~/SourceCode/debian, compared against the
authoritative guide at https://notes.sagredo.eu/en/qmail-notes-185/configuring-qmail-83.html.

The goal is to package and deploy qmail (the sagredo-dev patched variant)
on Debian 13 Trixie as a proper set of installable .deb packages, and
then configure a fully operational mail server in the Debian virtual machine.

** Critical Finding

The ~qmail_1.06-9_amd64.deb~ that has been built is the *plain* Debian
netqmail package — it does NOT include any of the sagredo/DSMR patches
(TLS, DKIM, SPF, SRS, chkuser, etc.).

The *correct* source to package is ~dsmr-qmail/dsmr-qmail-1.06.3/~, which
is a git repository of the sagredo-dev patched qmail. Its ~debian/~
subdirectory already contains packaging work in progress by the project
maintainer (Brian O'Reilly).

** netqmail-1.06 (Plain Debian Package — Reference Only)

This directory contains the standard Debian packaging of netqmail 1.06 as
maintained by Gerrit Pape. It has been built successfully as ~qmail_1.06-9~.

The built package is in ~netqmail-1.06/debian/qmail/~ (binary tree). Notable
difference from dsmr-qmail: it contains ~qmail-verify~ (recipient checking via
Andrew Richards' realrcptto patch) but NONE of the TLS, DKIM, SPF, SRS, or
chkuser functionality.

This package serves as a reference and can be discarded in favour of
packaging dsmr-qmail properly. It is however useful to compare the
~debian/rules~ build structure.

** qmail-run-2.0.2+nmu4

Service supervision and run scripts. Already built and packaged. Key files:

- ~run-qmail-send~, ~run-qmail-smtpd~, ~run-qmail-verify~ — supervision run scripts
- ~log-qmail-send~, ~log-qmail-smtpd~, ~log-qmail-verify~ — logging run scripts

- ~defaultdelivery~ — default delivery specification
- ~concurrencyincoming~ — concurrency settings
- ~daemontools.service~ — systemd unit file (the NMU addition by Brian O'Reilly)

*Important gap*: The sagredo guide configures THREE SMTP listeners:
- Port 25: qmail-smtpd (inbound, via tcpserver/ucspi-tcp6)
- Port 465: qmail-smtpsd (implicit SSL, via sslserver/ucspi-ssl)
- Port 587: qmail-submission (STARTTLS + auth required)

The current ~qmail-run~ package only has scripts for port 25 SMTP and
qmail-send. It will need extension or replacement for the sagredo
multi-port model. The sagredo guide uses its own ~supervise/~ directory
structure (populated by ~config-all~) rather than the Debian ~qmail-run~
package layout.

* The Sagredo Guide Requirements

** What the Guide Covers

The main guide at https://notes.sagredo.eu/en/qmail-notes-185/configuring-qmail-83.html
describes a full qmail mail server deployment using:

1. A pre-patched qmail source (the sagredo-dev fork at https://github.com/sagredo-dev/qmail)
2. daemontools v0.83 (sagredo fork)
3. ucspi-tcp6 v1.13.07 (fehcom.de)
4. ucspi-ssl v0.13.07 (fehcom.de)
5. vpopmail v5.6.13 (sagredo fork)
6. libsrs2 v1.0.18

** Installation Model in the Guide

The guide uses a *non-Debian package* installation model:
- ~package/install~ scripts (DJB-style)
- ~./config-all mx.mydomain.tld~ automated configuration script
- Manual ~supervise/~ directory setup
- Files go into ~/var/qmail/~

*Key tension*: The project is creating *Debian packages*, but the upstream
guide uses DJB-style direct installation. The Debian packaging work wraps
this into proper .deb files. The ~dsmr-qmail~ debian/ packaging translates
the upstream build into dpkg-compatible form.

* Key Decisions Required

1. *Debian install paths*: The Debian packaging puts qmail in ~/var/lib/qmail/~
   with ~/var/lib/qmail/control -> /etc/qmail~. The sagredo guide uses ~/var/qmail/~.
   A decision is needed: maintain the Debian path convention (with symlink) or
   change to use ~/var/qmail/~ directly.

2. *qmail-run vs custom supervise*: Use the Debian ~qmail-run~ package (extend it)
   or create new run scripts following the sagredo ~supervise/~ model. The current
   qmail-run NMU already has systemd support; extending it would maintain packaging
   discipline.

3. *daemontools version*: Debian 13 Trixie ships daemontools 1:0.76-14 in the
   official archive — simply ~apt-get install daemontools daemontools-run~. The
   local ~daemontools-0.76/~ source (version 0.76-10) is superseded by what is
   already in Trixie. The sagredo fork v0.83 remains an option if its specific
   features are needed.

4. *ucspi-tcp6 packaging*: Fetch from fehcom.de and create a Debian package, or
   investigate if there is a Debian-compatible alternative.

5. *vpopmail version*: Which of the three local versions (5.4.33, 5.6.9, ~vpopmail/~)
   to base the Debian packaging on, vs fetching sagredo's 5.6.13.

6. *MySQL vs CDB backend for vpopmail*: The sagredo guide uses MySQL. CDB is simpler
   and has no external database dependency. For initial deployment, CDB may be
   preferable.
